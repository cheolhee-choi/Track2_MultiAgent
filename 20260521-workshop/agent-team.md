## 목적
멀티 에이전트 오케스트레이션 대시보드 작업을 위해 역할을 분리하고, 각 역할의 산출물을 모아 최종 결과를 정리한다.

## 입력
- 제품 목표
- 대시보드 요구사항
- 화면/기능 범위
- 기존 코드베이스 정보
- 작업 우선순위와 제약조건

## 출력
- 실행 가능한 작업 분해안
- 각 에이전트의 역할 정의
- 우선순위가 반영된 실행 순서
- 리뷰/QA 기준

## 팀 구성

### 1. 기획 오케스트레이터
- 전체 요구사항을 쪼개고 작업 순서를 정한다.
- 중복 작업과 누락을 줄인다.
- 완료 기준: 팀이 따라갈 수 있는 작업 분해안이 나온다.

### 2. UI/UX 디자이너
- 대시보드 정보 구조, 레이아웃, 상태 표현을 설계한다.
- AI 티가 나지 않는 자연스러운 화면 구성에 집중한다.
- 완료 기준: 화면 흐름과 시각 원칙이 정리된다.

### 3. 데이터/상태 설계자
- 에이전트 상태, 큐, 로그, 이벤트, 결과물의 데이터 구조를 정의한다.
- 대시보드에서 필요한 최소 데이터 모델을 제안한다.
- 완료 기준: 화면이 읽을 수 있는 데이터 스키마가 정리된다.

### 4. 구현 에이전트
- 실제 코드와 연결 가능한 UI 구조를 만든다.
- 시각 요소보다 동작 우선으로 구현한다.
- 완료 기준: 기능이 동작하는 초안이 만들어진다.

### 5. 코드 리뷰어
- 구현물의 결함, 애매한 부분, 설계 누락을 비판적으로 본다.
- 수정 대신 문제를 명확히 적는다.
- 완료 기준: 개선 포인트가 빠짐없이 정리된다.

### 6. TDD 에이전트
- 핵심 흐름을 검증하는 테스트 초안을 만든다.
- 상태 전이, 실패 케이스, 경계 조건을 우선한다.
- 완료 기준: 테스트 코드 초안이 준비된다.

### 7. QA/검증 에이전트
- 실제 사용 흐름 기준으로 결과를 확인한다.
- 빈 화면, 오류 화면, 로딩 상태를 점검한다.
- 완료 기준: 사용자 관점 검증 체크리스트가 완성된다.

## 운영 원칙
- 먼저 계획, 다음 설계, 그다음 구현, 마지막 검증 순서로 움직인다.
- 각 에이전트는 자기 역할 외 작업을 하지 않는다.
- 모호한 요구는 즉시 표시하고, 추측으로 채우지 않는다.
- 산출물은 짧고 명확해야 한다.
- 대시보드 핵심은 상태 가시화, 작업 흐름, 병목 파악이다.

## 추천 보강 항목
- 실시간 상태 패널
- 에이전트 실행 로그 뷰
- 작업 큐 및 우선순위 뷰
- 실패/재시도 추적
- 수동 승인 흐름

## 완료 기준
- 각 역할의 책임이 분리된다.
- 오케스트레이션 대시보드 구현을 바로 시작할 수 있다.
- 다음 작업자가 읽어도 실행 순서가 명확하다.
